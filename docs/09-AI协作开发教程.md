# AI 协作开发教程：从零构建牛奶品质分级 WebApp

> 本文档记录如何借助 AI（如本助手）完成从需求分析到系统交付的全流程开发实践。以「牛奶品质分级系统」为例，演示每个阶段的人机协作方法、提示词技巧与注意事项。

> **版本注记（v2.1）**：本教程写于项目 v1.0 时期，记录的是「数据→模型→后端→前端→文档」五阶段基础流程。项目后续已升级至 v2.1 企业落地版：v2.0 新增 Agent 智能体（根因分析/改进建议/趋势/异常检测/报告/知识问答），v2.1 新增企业落地能力（奶源来源档案、优质优价定价、企业质量日报）与任务书缺口补齐（相关性分析/基线对比/CSV 预览/个人中心）。教程中的协作方法论（分阶段递进、每阶段人工确认）依然适用，具体产物以 [docs/15-项目交付清单](./15-项目交付清单.md) 为准。

## 一、协作总纲

### 1.1 核心思路

AI 协作开发不是「让 AI 一次性写出所有代码」，而是**分阶段递进、每阶段人工确认、AI 补全细节**：

```
用户定方向 → AI 给选项 → 用户选择 → AI 执行 → 用户验证 → 进入下一阶段
```

### 1.2 角色分工

| 角色 | 职责 |
|------|------|
| **用户（产品经理/开发者）** | 提供任务书/PRD、做方向性决策（技术选型、优先级）、验证成果 |
| **AI（全栈工程师助手）** | 分析需求、提供选项、写代码、跑测试、出文档、排查问题 |

### 1.3 开发节奏建议

| 阶段 | 预计时间 | 关键产出 |
|------|---------|---------|
| 需求分析 | 0.5–1h | PRD、架构决策 |
| 模型训练 | 1–2h | 数据集、模型文件、评估报告 |
| 后端开发 | 2–3h | FastAPI 服务、9 个接口、数据库 |
| 前端开发 | 2–3h | React 页面、组件、联调 |
| 文档与测试 | 1–2h | 测试报告、PPT、RAG 语料库 |

> 单人 + AI 协作，完整项目约 **1–2 天**可交付。

## 二、阶段一：需求分析与系统设计

### 2.1 输入

向 AI 提供：
- **项目任务书**（Word/PDF）：包含背景、目标、技术约束、预期输出
- **参考资源**：如 Kaggle 数据集链接、竞品网址、设计参考

### 2.2 协作流程

**步骤 1：AI 分析任务书**

提示词示例：
```
请帮我仔细分析这份项目任务书，提取关键需求、技术约束、交付物清单，
并提供选项引导我怎么开启第一步。
```

AI 会输出：
- 需求拆解（功能/非功能）
- 技术选型建议（含理由）
- 多选题引导（如：先验证模型还是先搭前端？）

**步骤 2：用户做关键决策**

AI 给出选项卡片，用户选择：
- 开发顺序：「数据+模型验证先行」vs 「前后端并行」
- 协作模式：「AI 写代码我跟着学」vs 「我动手 AI 指导」
- 前端 UI 库：Ant Design vs TailwindCSS

> **技巧**：让 AI 在关键节点给选项，避免一次性输出过多导致决策疲劳。

**步骤 3：输出 PRD 与架构设计**

AI 根据决策输出：
- `PRD.md`：功能清单、用户故事、验收标准
- `系统架构.md`：技术栈、模块划分、数据流图
- `数据库设计.md`：ER 图、表结构、字段约束

## 三、阶段二：数据探索与模型训练

### 3.1 输入

- 数据集来源（如 Kaggle URL）
- 目标指标（准确率、F1 阈值）

### 3.2 协作流程

**步骤 1：AI 下载并探索数据**

提示词：
```
从 Kaggle 下载 milk_quality.csv，做 EDA：
1. 字段统计与分布
2. 缺失值与异常值
3. 类别不平衡情况
4. 特征相关性
```

AI 自动执行：
- 下载数据（处理国内网络慢的问题，自动切换镜像）
- 运行 EDA 脚本
- 输出统计报告

**步骤 2：基线模型对比**

AI 训练多个基线模型并对比：

| 模型 | 测试集准确率 | 宏平均 F1 |
|------|------------|----------|
| 决策树 | ~95% | ~0.94 |
| 随机森林 | ~98% | ~0.97 |
| **XGBoost** | **99.1%** | **0.991** |

> AI 自动发现并修复数据问题（如列名拼写错误 `Temprature`→`Temperature`）。

**步骤 3：模型固化与调参**

提示词：
```
用 Pipeline 封装预处理（StandardScaler）+ XGBoost，
GridSearchCV 调参，保存 joblib 模型和 metadata JSON。
```

AI 输出：
- `models/milk_quality_pipeline.joblib`（可部署的 Pipeline）
- `models/model_metadata.json`（测试指标、特征重要性、超参数）
- `reports/`（混淆矩阵图、特征重要性图、评估报告）

### 3.3 本阶段关键技巧

| 问题 | AI 解决方法 |
|------|------------|
| 数据集 License 不明 | AI 自动标注风险，提醒商用前确认 |
| Python 3.13 无 xgboost wheel | AI 自动降级到 3.12，避免源码编译 |
| pip 国内慢 | AI 自动切换清华/阿里镜像 |
| 列名拼写错误 | AI 清洗代码自动容错（CSV 接口也做兼容） |

## 四、阶段三：后端 API 开发

### 4.1 输入

- 已训练好的模型文件
- PRD 中的功能清单
- 数据库设计文档

### 4.2 协作流程

**步骤 1：AI 生成后端骨架**

提示词：
```
基于以下设计，生成 FastAPI 后端代码：
- 数据库：SQLite + SQLAlchemy 2.0
- 认证：JWT + bcrypt
- 模型推理：加载 joblib Pipeline
- 接口清单：预测、CSV批量、历史记录、登录注册、指标字典、模型信息
```

AI 生成完整后端结构：
```
backend/
├── app/
│   ├── main.py          # FastAPI 入口 + CORS + 路由注册
│   ├── config.py        # 路径 + JWT 配置
│   ├── database.py      # SQLAlchemy engine + session
│   ├── models_db.py     # ORM: User / GradeRecord / Indicator
│   ├── schemas.py       # Pydantic v2 请求/响应模型
│   ├── auth.py          # JWT 签发/验证 + bcrypt
│   ├── ml_model.py      # 模型加载 + 推理封装
│   ├── seed.py          # 指标字典初始化
│   └── routers/
│       ├── predict.py   # 单条预测 + CSV批量
│       ├── auth.py      # 注册 + 登录
│       ├── history.py   # 历史记录 + CSV导出
│       ├── indicators.py# 指标字典查询
│       └── model.py     # 模型元数据查询
└── requirements.txt
```

**步骤 2：逐接口测试**

AI 用 curl 逐一验证：

```bash
# 匿名预测
curl -X POST http://127.0.0.1:8000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"ph":6.6,"temperature":35,"taste":1,"odor":0,"fat":1,"turbidity":1,"colour":255}'

# 登录获取 Token
curl -X POST http://127.0.0.1:8000/api/auth/login \
  -d '{"username":"test","password":"pass"}'

# 带 Token 预测（保存到历史）
curl -X POST http://127.0.0.1:8000/api/predict \
  -H "Authorization: Bearer <token>" \
  -d '{...}'
```

每完成一个接口，AI 输出测试用例文档。

### 4.3 本阶段关键技巧

| 问题 | AI 解决方法 |
|------|------------|
| 匿名用户也被要求登录 | AI 发现 `OAuth2PasswordBearer(auto_error=True)`，改为 `auto_error=False` |
| 模型接口 404 | AI 发现进程是旧版本，重启后端解决 |
| CSV 批量列名容错 | AI 在接口中自动清洗 `Temprature`/`temprature` 等变体 |
| SQLite 并发 | AI 使用 `check_same_thread=False` + 依赖注入管理 session |

提示词：
```
基于 UI/UX 设计文档，生成 React + Vite + Ant Design 前端代码：
```

**步骤 2：联调验证**

AI 启动 Vite dev server，验证：
1. `npm run build` 无 error
2. `/api` 代理到后端 8000 正常
3. 登录→预测→保存历史→查看历史 全流程通过

### 5.3 本阶段关键技巧

| 问题 | AI 解决方法 |
|------|------------|
| vite build 清空 dist 失败 | AI 在 `vite.config.js` 加 `emptyOutDir: false`（本机 safe-delete 拦截） |
| npm 国内慢 | AI 使用 `registry.npmmirror.com` |
| 后端字段名大小写 | AI 统一前端传小写 `ph/temperature/...`，与后端 schema 对齐 |
| 图表 CJK 字体乱码 | AI 将图表标签改为英文，避免 matplotlib 中文字体问题 |

## 七、高效协作技巧

### 7.1 提示词模板

**类型 A：分析类**
```
请分析 [文件/链接]，提取：
1. 关键需求点
2. 技术约束
3. 交付物清单
4. 潜在风险
```

**类型 B：决策类**
```
基于以上分析，请提供 2-3 个选项帮我选择下一步方向，
每个选项说明优缺点和所需时间。
```

**类型 C：执行类**
```
请基于 [文档/设计] 生成 [代码/文档]，要求：
- 技术栈：[具体版本]
- 约束：[性能/安全/兼容]
- 输出：[文件路径]
```

**类型 D：排错类**
```
遇到以下错误：[错误日志]
已尝试：[措施]
请分析根因并提供修复方案。
```

### 7.2 沟通原则

1. **分阶段确认**：每完成一个里程碑，让 AI 总结成果并等待确认再进入下一阶段
2. **提供参考**：给 AI 网址/截图/文件作为上下文，提高输出准确性
3. **及时反馈**：发现问题立即指出，AI 会快速修复（如「选了差还是给高品质评价」）
4. **利用选项**：在复杂决策点让 AI 给选项，减少思考负担

## 八、常见问题与排错

### 8.1 环境类

| 问题 | 原因 | 解决 |
|------|------|------|
| Python 3.13 装不上 xgboost | 无预编译 wheel | 降级到 Python 3.12 |
| pip 下载极慢 | 默认 pypi.org 国内慢 | 换清华/阿里镜像 |
| vite build 失败 | safe-delete 拦截 rm | `emptyOutDir: false` |
| npm install 慢 | 默认 registry 慢 | `registry.npmmirror.com` |

### 8.2 代码类

| 问题 | 原因 | 解决 |
|------|------|------|
| `/api/model/info` 404 | 后端进程是旧版本 | 重启 uvicorn |
| 匿名预测 403 | `auto_error=True` | 改为 `auto_error=False` |
| Pipeline 预测报错 | 传了 numpy array | 传 pandas DataFrame |
| CSV 批量列名错 | 原始数据拼写错误 | 接口层自动清洗 |

### 8.3 模型类

| 问题 | 原因 | 解决 |
|------|------|------|
| XGBoost 3.x `num_class` 报错 | API 变更 | 移除 `num_class` 参数 |
| 混淆矩阵 label 不匹配 | 传了字符串标签 | 传整数编码 |
| 特征重要性图为空 | 未调用 `get_booster()` | Pipeline 中提取 booster |
